## Capability comparison based on inspected implementations

| Concern | Evidence in other tools | GeoCrop status in current working tree | Consequence |
|---|---|---|---|
| Execution visibility | eo-learn EOExecutor.run supports configurable process/thread workers; results explicitly distinguish failed/successful executions and report timing/workers. openEO BatchJob has created/queued/running/canceled/finished/error state, logs and polling error handling. | pipeline.Runner.stage records a fingerprint, runtime and info after success; workflow is sequential and has no explicit running/failed stage record. `_done` checks only saved fingerprint/output existence. | Reliable recovery and reporting should precede adding more parallelism. Cache validity needs a complete output contract and interrupted-stage protection. |
| STAC-to-pixel interoperability | StackSTAC stacks STAC Items as `(time,band,y,x)` Dask-backed arrays on a common grid, handles nodata and asset scale/offset. `stack` exposes resolution, bounds, resampling, dtype, rescale and chunk size. | stac.discover only exports CSV asset href inventory. Core import expects SAFE or scene folders. Generic STAC assets cannot directly enter the documented pipeline. | A local/COG STAC Item importer can bridge provider-neutral discovery to the existing scene contract, respecting radiometry and masks. |
| Per-band resampling and temporal grouping | odc.stac.load supports per-band resampling/dtype, precise `geobox`/`like` grid, time/solar_day/id grouping and deterministic time/id order for fusing. Optional `chunks` builds Dask arrays. | raster.read_aligned already supports per-call resampling and common grids; S2 masks use nearest, continuous bands bilinear. S2 has same-day mosaicking. No STAC loader route. | Preserve these existing correct distinctions when adding a STAC adapter; importing SCL with bilinear would be a scientific regression. Deterministic overlap handling should be explicit. |
| Training/benchmark ecosystem | TorchGeo supplies geospatial datasets, spatial sampling, dataset union/intersection with common CRS/resolution, multispectral pretrained weights and datamodules with documented train/validation/test splits. | GeoCrop has synthetic software checks, spatial CV, optional custom U-Net/TempCNN and externally supplied references. No standard downloadable real-data benchmark adapter or measured comparison to pretrained multispectral baselines. | A true quality claim needs a versioned real-data evaluation protocol and separate test/reference sets. A new neural dependency alone cannot establish better accuracy. |
| Output catalogues | STAC ecosystems load data from metadata such as raster/projection/band information. | export.stac_item builds a minimal STAC 1.0/classification/projection Item; it does not validate against schemas, includes three raster assets unconditionally, omits per-band raster metadata and explicit provenance/model links. | Standards-validated output plus asset existence/grid validation is a small, testable reliability gain that benefits all downstream consumers. |
| Scale and memory | StackSTAC and odc-stac can use chunked Dask loading; eo-learn can parallelize independent workflow executions. | GeoCrop is already windowed and runs on a single workstation without Dask. tsfeatures allocates `(block_pixels, n_scenes)` observations per index. | Do not claim GeoCrop is faster or slower without measurements. A resource planner and bounded concurrency are reasonable future features; a full Dask rewrite is not necessary for correctness. |

## Recommended improvements, in priority order

1. **Harden execution and resume semantics now.** Persist running/succeeded/failed state with stage exceptions and atomic state writes. Validate all output companions before skip, not only a representative TIFF/model file. Never mark a partially written output as reusable. Include scene metadata/asset changes and time-series inputs in fingerprints. Tests: injected stage failure, missing companion file, modified input asset, corrupt state/report, successful repeat skip. This is inspired by the explicit outcome handling in eo-learn/openEO, not copied code.

2. **Validate and enrich STAC export now.** Build assets from files that actually exist; validate required class/probability/uncertainty alignment and band legend; include raster-band nodata/data type descriptions, actual pixel footprint/projection and traceable source/model/run-manifest assets where supplied. Resolve relative hrefs from the item output location and perform offline STAC/core/extension schema tests using trusted packaged schemas (do not suppress validation if a network schema request fails). Tests: valid item parse/validate, missing raster, mismatched grid/legend, no-EPSG CRS, self-contained exported directory. This improves interoperability without changing inference.

3. **Add an optional STAC scene adapter, not a second pipeline.** Accept a saved STAC Item/ItemCollection plus explicit asset-to-band mapping and reference grid. Read local or HTTP COG windows through rasterio; apply declared scale/offset exactly once; mask nodata before resampling; keep categorical SCL/cloud masks nearest; copy only selected data into existing scene folders with item/asset provenance. Fail if required radiometry is unknown rather than guessing from asset names. Tests can use tiny local COGs and STAC JSON, requiring no credentials. Full Dask integration and cloud signing should remain optional follow-ups.

4. **Create a versioned real-data benchmark protocol.** Pin dataset source/version/license, reference split and artifact hashes; compare RF/ExtraTrees and optional pretrained baselines on the same untouched independent test set; report class-specific metrics, confidence intervals, calibration, runtime and peak memory. Keep synthetic outputs explicitly separate. A lightweight benchmark runner can be added now, but no real-world superiority claim should be made until data and comparable runs are available.

## Limits and safe reuse

These frameworks have different scopes: workflow library, geospatial deep-learning library, remote process client and STAC raster loaders are not interchangeable crop-declaration engines. No accuracy, speed or operational superiority has been measured in this review. No third-party source was copied into GeoCrop and no license compatibility conclusion is asserted here; inspect each project's license and model/data terms before introducing a dependency, weights or source reuse.
